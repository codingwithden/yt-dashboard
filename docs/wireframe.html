YT Dashboard Blueprint

One app. Three tools. Each one takes something messy from a creator and hands back something ready to use.

Idea Organizer

Paste a brain dump. Get video cards on a board.

InMessy notesOutCards with title, hook, format, statusCostAbout 5 cents per run

Thumbnail Tester

Upload 2 to 6 thumbnails. See which one wins and why.

InImages and a titleOutScores, reasons, accessibility warningsCostAbout 1 cent per thumbnail

File Organizer

Point at a folder of footage. Get clean names and sorted subfolders.

InA local folderOutRenamed, tagged, sorted filesCostAbout half a cent per file
Video never leaves the laptop. Only tiny frame samples and thumbnails go to the AI. Keys stay on the server.

Postgres on Supabase

Data model

Everything hangs off a workspace. Row-level security means a user can only ever read rows in workspaces they own. Start with the tree, then read the cards.

  • auth.users Supabase login
    • profiles who they are, what plan
    • subscriptions Stripe mirror
    • feature_usage monthly counters
    • ai_usage one row per AI call, with cost
    • integrations Notion, Google Drive tokens
    • workspaces one per channel, Pro can have many
      • idea_dumps the raw paste
        • projects one card on the board
      • thumbnail_tests one upload batch
        • thumbnail_variants one image with its scores
      • naming_rules saved name patterns
      • organizer_sessions one folder run
        • organizer_files one row per file in the review table

Account and money

Owned directly by the user. Written mostly by the Stripe webhook and the AI routes.

What happens on one AI click

One route handler per feature, all built the same way. If you understand this once, you understand all of them.

Browser preps the inputResize thumbnails, grab video frames, or grab the text.client
Check who it isSupabase session. No session, no call.app/api/*/route.ts
Check the limitRead plan from profiles, compare to feature_usage. Over the cap: return "upgrade" instead.lib/usage
Bump the counterAtomic Postgres function. Two fast clicks can't double-spend.lib/usage
Ask ClaudeStructured output so the answer is always valid JSON. Stream it back.lib/anthropic
Log cost, returnWrite ai_usage with tokens and dollars. Send result to the page.lib/usage
Routes: POST /api/ideas/organize, POST /api/thumbnails/score, POST /api/organizer/describe. Plus /api/stripe/checkout, /api/stripe/portal, /api/stripe/webhook. Everything else (saving cards, moving columns, editing names) is a Server Action, no API route needed.

Known problems and the plan for each

Risks

File Organizer only works in Chrome, Edge, Brave, Arc on desktop.Safari and Firefox can't write to local folders.Other browsers get a read-only preview and a downloadable rename script. Phones get a friendly "use your computer" note.
ffmpeg.wasm is a 30 MB download and its fast mode breaks Stripe's embedded forms.Grab frames with a hidden video tag and canvas instead. Covers mp4, webm, and most mov. Load ffmpeg.wasm lazily only for odd codecs like ProRes.
Moving big files into subfolders can be slow.The browser's move method isn't reliable yet outside its private storage.Use move where it works, copy then delete elsewhere. Write an undo log before touching anything.
Scoring 6 thumbnails can take 20 to 40 seconds.Vercel Hobby cuts functions off at 10 seconds.Vercel Pro and streaming responses from day one. User sees scores appear one by one.
Free users could run up the bill.Every AI route checks the counter first. Counters bump atomically. Free gets hard caps on all three features.
Stripe webhook glitches could give or take access by mistake.Only the webhook changes plans. Every event id is stored, so a replay is a no-op. Success page just says "thanks."
